# AIとベクトル埋め込みを使った4Dのセマンティックアイコン検索

Karim Meghraoui（4D Morocco テクニカルサービスエンジニア）

テクニカルノート 26-04

## 概要

セマンティック検索（semantic search）は、キーワードの完全一致に頼るのではなく、ユーザーのクエリの意味を理解することで検索結果の関連性を高める、高度な情報検索の手法です。このテクニカルノートでは、4D AI KitとOpenAIの埋め込みAPIで生成したベクトル埋め込み（vector embedding）を使い、4Dアプリケーションにセマンティック検索を実装する実践的な方法を紹介します。

## はじめに

このドキュメントでは、埋め込み、ベクトル類似度、ランキングの仕組みといった基本的な概念を説明し、ORDAと4D.Vector型を使ってこれらの概念を4D環境で活用する方法を示します。また、動的な埋め込み生成と事前計算済みのベクトルを組み合わせ、パフォーマンスを最適化しながら外部APIの利用を減らすハイブリッド検索の戦略についても説明します。

詳しい解説と注釈付きのコード例を通して、このテクニカルノートは、さまざまなユースケースに対応できる、効率的でスケーラブルな、使いやすいセマンティック検索システムを設計・実装するために必要な知識を開発者に提供します。

## コンセプトの概要

セマンティック検索は、キーワードの一致だけに頼るのではなく、クエリの意味と意図を理解することに重点を置いた検索手法です。その基盤となるのが埋め込み（embedding）で、これは機械学習モデルによって生成される、テキストの数値表現です。

テキストを埋め込みに変換すると、意味的な特徴を表す数値のベクトルになります。意味の似たテキストからは、**ベクトル空間の中で互いに近い位置にある**ベクトルが生成されます。

![](fig-01)

ベクトルどうしを比較することで、2つのテキストがどの程度関連しているかを判断できます。

アイコンライブラリの場合、セマンティック検索を使うと、メタデータの完全一致ではなく概念的な類似性にもとづいてアイコンを検索できます。

### アプリケーションの概要

サンプルアプリケーションには、次のものが含まれています：

![](fig-02)

- ユーザーがクエリを入力する検索フィールド
- 事前計算済みの埋め込みがデータベースに保存されている、3つの定義済みキーワードボタン
- 結果の精度を調整する類似度しきい値のスライダー
- 検索の前に必ず使用する「Configure OpenAI API Key」ボタン
- アイコン名、類似度スコア、画像を表示する結果パネル

検索を実行すると、システムはクエリのベクトル埋め込みを生成し、各アイコンについて保存されている埋め込みと比較します。意味的にもっとも関連性の高いアイコンが、類似度の順に並べられて返されます。

### 主要なコンポーネント

#### テキストと画像

各アイコンには2種類の情報が含まれています：

- 画像データ：インターフェースに表示されるアイコンの見た目
- テキストのメタデータ：アイコン名や関連付けられたタグなど

テキストのメタデータは、アイコンの意味を表す埋め込みの生成に使われます。

#### 埋め込みの生成と保存

アイコンのメタデータから生成した埋め込みは、4D.Vector型を使ってデータベースに直接保存されます。

したがって、各アイコンのエンティティには次のものが含まれます：

- 名前
- ピクチャー
- タグ
- ベクトル埋め込み

これらの表現は前処理の段階で一度だけ生成され、その後のすべてのクエリのためにデータベースに保存されます。

次のコードは、テキストをベクトルに変換して保存する方法を示しています。埋め込みは外部のモデルを使って生成され、エンティティの一部として保存されます。検索のたびに埋め込みサービスを呼び出さずに済むため、この手順はパフォーマンスにとって欠かせません。

**例**：

```4d
$embeddingResult:=$embeddingAPI.create($iconEntity.tags; $model)
If ($embeddingResult.vector#Null)
  $iconEntity.vector:=$embeddingResult.vector
  $iconEntity.save()
End if
```

ベクトルがデータベースに保存されていれば、ORDAで類似度の比較をすばやく効率的に実行できます。

#### 類似度の計算

ベクトルが用意できたら、システムはそれらがどの程度似ているかを判断する必要があります。これにはコサイン類似度（cosine similarity）を使います。コサイン類似度は、2つのベクトルのなす角を評価する数学的な尺度です。

システムはテキストどうしを直接比較するのではなく、それぞれのベクトル表現を比較します。2つのベクトルが似た方向を向いていればコサイン類似度は高くなり、元のテキストが意味的に関連していることを示します。

このアプリケーションでは、類似度はデータベースのクエリの中で直接計算されます。

次のクエリは、クエリベクトルを保存済みのベクトルと比較し、類似度のしきい値でフィルターをかけ、類似度の降順で結果を並べ替えます：

```4d
$iconSelection:=ds.Icon.query("vector >= :1 order by vector desc"; \
  {vector: $embeddingResult.vector; metric: mk cosine; \
  threshold: $thresholdPercentage/100}
```

コサイン類似度を使うことで、結果は意味的な関連性にしたがって順位付けされます。これは、ベクトルフィールドに対するORDAクエリの威力を示すものです。

#### 順位付けされた結果の表示

類似度を計算したら、システムは結果をわかりやすい形で表示する必要があります。各結果には、クエリとどの程度一致しているかを表す類似度スコアが関連付けられます。

次のコードは、スコアを計算して結果に付加する方法を示しています：

```4d
For each ($iconEntity; $iconSelection)
  $resultWithScore:=New object()
  $resultWithScore.name:=$iconEntity.name
  $resultWithScore.picture:=$iconEntity.picture
  $resultWithScore.score:=100*($iconEntity.vector.cosineSimilarity(\
    $embeddingResult.vector))
  $results.push($resultWithScore)
End for each
```

この手順で、クエリの生の結果が、内容と読みやすい類似度スコアの両方を含む構造化されたオブジェクトに変換されます。順位付けによってもっとも関連性の高い項目が先頭に表示されるため、使いやすさと検索の効率が向上します。

すべての検索結果は、4Dのリストボックスを使って使いやすいインターフェースで簡単に表示できます。名前や類似度スコアによる並べ替えも、リストボックスなら追加のコードなしでそのまま行えます。

### ユースケース

この例はアイコンライブラリを対象としていますが、セマンティック検索は次のような多くの分野に応用できます：

- 文書リポジトリ
- ナレッジベース
- メディアライブラリ
- 製品カタログ
- 画像コレクション

いずれの場合も、メタデータで使われている正確なキーワードをユーザーが知らなくても、セマンティック検索によって関連する項目を見つけやすくなります。

## 設計とアーキテクチャ

### 必要条件／前提条件

このアプリケーションでセマンティック検索を実装するには、次の前提条件を満たす必要があります：

- データアクセスにORDAを使用する4Dプロジェクト
- 4D.Vector型のサポート
- プロジェクトの依存関係に追加された4D AI Kitコンポーネント
- 埋め込みを生成するためのOpenAI APIキー
- メタデータが関連付けられたアイコンのデータセット（このテクニカルノートのサンプルアプリケーションでは、GoogleのMaterial Design Iconsプロジェクト（https://fonts.google.com/icons）を使用しました）

埋め込みAPIを使う前に、4D AI Kitコンポーネントをプロジェクトの依存関係に追加しておく必要があります。

### 使用している技術

この実装は、4Dプラットフォームが提供するいくつかの技術にもとづいています。

- **ORDA**：エンティティへのアクセスとデータベースのクエリに使用します。
- **4D.Vector**：埋め込みベクトルをデータベースに直接保存するために使用します。
- **4D AI Kit**：OpenAIのサービスを利用するための簡潔なインターフェースを提供します。

**OpenAI APIキーの扱い**：アプリケーション内では、OpenAI APIキーをシンプルかつ安全な方法で扱っています。キーは永続的に保存されないため、データファイルや設定ファイルを通じて誤って漏えいしたり、意図せず拡散したりすることがありません。そのかわり、デモアプリケーションを起動するたびにキーを入力する必要があります。この方法はデモアプリケーションには安全で扱いやすいものですが、キーを永続的に保存する必要がある、より複雑なシナリオでは、キーの安全を確保するために適切なセキュリティ対策を講じる必要があります。

### OpenAI APIキーの管理

ユーザーはダイアログでキーを入力または更新できます。ダイアログには、以前に保存した値があれば自動的に入力されています。これにより、そのつどコードを変更することなく、アプリケーション全体でキーを再利用できます。

4Dでのキーの扱い方の例：

```4d
var $key : Text
$key:=Request("Enter your OpenAI Key:"; GetOpenAIKey())
If (OK=1)
  SetOpenAIKey($key)
End if
```

GetOpenAIKey()は、キーがあればStorageから読み出します：

```4d
Use (Storage)
  If (Storage.openAIKey#Null)
    Use (Storage.openAIKey)
      $key:=Storage.openAIKey.value
    End use
  End if
End use
```

SetOpenAIKey($key)は、Storageのオブジェクトが存在することを確認してから、キーを保存します：

```4d
Use (Storage)
  If (Storage.openAIKey=Null)
    Storage.openAIKey:=New shared object()
  End if
  Use (Storage.openAIKey)
    Storage.openAIKey.value:=$key
  End use
End Use
```

この仕組みは、4DのStorageと共有オブジェクトを利用して、OpenAIの認証情報を永続化せずに安全かつ再利用可能な方法で管理し、埋め込みAPIなどのAI Kitのサービスにシームレスにアクセスできるようにします。

> **訳注**：日本語版のデモでは、ここで説明している方法のかわりに、4D AI Kitのプロバイダー設定ファイル`Project/Sources/AIProviders.json`からOpenAI APIキーを読み込みます。同じフォルダーにある`AIProviders.example.json`を`AIProviders.json`という名前でコピーしてキーを設定するか、4D 21 R3ではストラクチャー設定の「AI」ページでOpenAIのプロバイダーを追加してください。このファイルはGitの管理対象から除外されているため、キーが誤ってリポジトリにコミットされることはありません。ファイルはJSONとして直接読み込むので、4D 21 LTSでも動作します。このため、日本語版のデモには「Configure OpenAI API Key」ボタンとSetOpenAIKeyメソッドはありません。

### 課題と解決策

従来のアイコン検索システムは、キーワードの完全一致に頼っています。アイコンには名前やタグなどのメタデータが関連付けられ、クエリに同じ単語が含まれている場合にのみ結果が返されます。

この方法には限界があります。たとえば、「robot automation machine」というタグが付いたアイコンは、ユーザーが「automated system」で検索しても表示されないことがあります。どちらの表現も似た概念を表しているにもかかわらずです。

この限界を解消するため、このアプリケーションではベクトル埋め込みにもとづくセマンティック検索を使用しています。

ユーザーが検索プロンプトを送信するたびに、プロンプトは埋め込みモデルで処理され、入力されたテキストが数値のベクトル表現に変換されます。これらのベクトルは、多数の次元にわたってプロンプトの意味をとらえています。

下の図の左側はキーワードマッチングを示しています。クエリは個々の単語に分割され、システムはデータの中から完全に一致するものを探します。この方法はシンプルで高速ですが、同じ単語が使われている場合にしか機能しないため、同義語や言い換えを見逃してしまいます。

右側はセマンティック検索を示しています。インデックス作成の段階で、すべてのレコードが埋め込みモデルによってベクトルに変換されます。クエリの実行時には、クエリもベクトルに変換され、類似度関数を使って保存済みのベクトルと比較されます。これにより、使われている単語が異なっていても、意味にもとづいて結果を見つけることができます。

![](fig-03)

この方法では：

- 各アイコンを説明するテキストのメタデータが、ベクトル埋め込みに変換されます
- ユーザーの検索クエリも、同じモデルを使ってベクトルに変換されます
- システムは、類似度の指標を使ってこれらのベクトルを比較します

下の図は、単語やフレーズが意味的な類似性にもとづいてベクトル空間の中でどのように表されるかを示しています。クエリ「robot automation machine」は、共通のキーワードがないにもかかわらず、意味が関連しているため、フレーズ「automated system」の近くにあります（類似度：高）。ゆるやかに関連する語はより離れた位置にあって類似度が低く、無関係な語はもっとも遠くにあり、意味的なつながりがないことを示しています。この図から、埋め込みモデルが単語の完全一致を超えて意味をとらえていることがわかります。

![](fig-04)

埋め込みは単語どうしの意味的な関係をとらえるため、異なる言い回しや言語が使われていても、システムはクエリと概念的に関連するアイコンを検索できます。

## アプリケーションのワークフロー

### ワークフローの全体像

セマンティック検索のワークフローは、2つの**主要なフェーズ**で構成されています。

**フェーズ1：データのインポートとベクトル化**

アイコンは4DのResourcesフォルダーからインポートされ、メタデータとともにデータベースに保存されます。

プロジェクト内のResourcesフォルダーには、Material Design Iconsプロジェクト（https://fonts.google.com/icons）から抽出したアイコンの一部（PNG形式）とタグの一覧（JSONファイル）が置かれています。

次のコードは、Resourcesフォルダーにあるアイコンファイルごとに、新しいIconエンティティ（Iconテーブル内）を作成します。

各アイコンのエンティティは、名前（テキスト型）、画像（ピクチャー型）、タグの一覧（スペース区切りで1つの文字列として保存）、関連付けられたベクトル（4D.Vector型）を持ちます。

まず各アイコンの名前、タグ、ピクチャーのデータを設定し、ベクトルのフィールドは空（null）のままにしておきます。

```4d
$iconEntity:=ds.Icon.new()
$iconEntity.name:=$iconFile.name
$iconEntity.picture:=$iconPicture
$iconEntity.tags:=$iconTags[$iconFile.name].join(" ")
$iconEntity.vector:=Null
$iconEntity.save()
```

> **訳注**：日本語版のデモには、アイコンのPNGファイルとタグのJSONファイルは含まれていません。かわりに、Iconテーブルと（定義済みのプロンプトを保存する）Promptテーブルのレコードを、4Dの書き出しファイル（Resourcesフォルダーの`Icon.4ie`と`Prompt.4ie`、および読み込み設定の`.4si`ファイル）として同梱しています。起動時にテーブルが空であれば、_ImportIconsAndTagsメソッドがIMPORT DATAコマンドでこれらを読み込みます。レコードには埋め込みのベクトルも含まれているため、フェーズ1とフェーズ2の処理を実行しなくても、すぐに検索を試すことができます。

**フェーズ2：埋め込みの生成**

各アイコンのタグは、4D AI Kitを通じてOpenAIを使い、埋め込みベクトルに変換されます。

すべてのデータがデータファイルに保存されたら、すべてのアイコンのエンティティを順に処理し、関連付けられたタグからベクトル埋め込みを計算します。埋め込みサービスには4D AI Kitを通じてOpenAI APIでアクセスし、「text-embedding-ada-002」モデルを使用します。このモデルは、入力されたテキストを、その意味をとらえた数値表現（ベクトル）に変換します。

```4d
var $model : Text
$model:="text-embedding-ada-002"
var $embeddingAPI : cs.AIKit.OpenAIEmbeddingsAPI
$embeddingAPI:=GetOpenAIEmbeddingAPI()
$embeddingResult:=$embeddingAPI.create($iconEntity.tags; $model)
```

得られたベクトルは、アイコンのエンティティに保存されます。

この処理は通常、**ベクトル化の段階で一度だけ実行されます**。

### 埋め込みの保存戦略

埋め込みはベクトル化の段階で生成され、データベースに直接保存されます。ORDAでは、エンティティで4D.Vector型のフィールドを使用でき、ベクトルフィールドに対して高速で最適化されたベクトルクエリを実行できます。

この方法なら、クエリのたびにベクトルを計算し直す必要がないため、検索を高速に保つことができます。

埋め込みを生成し直す必要があるのは、新しいアイコンを追加したときや、メタデータを変更したときだけです。

### 類似度の計算

ユーザーが検索クエリを入力すると、そのテキストは、インデックス作成時と同じモデルを使って埋め込みベクトルに変換されます。

次に、アプリケーションは、このベクトルを保存済みのアイコンのベクトルと比較する類似度クエリを実行します。4Dでは、ベクトル検索用の引数を指定して.query()関数を一度呼び出すだけで、これを簡単に実行できます。

結果は類似度の順に並べ替えられ、しきい値を使って関連性の低い結果を除外できます。

### ハイブリッド検索の戦略

サンプルアプリケーションでは、2種類の検索を紹介しています。

**1. OpenAIを使った動的な検索**

ユーザーが任意のプロンプトを送信すると、システムはOpenAIを使ってベクトル埋め込みを生成し、アイコンのデータセットの事前計算済みの埋め込みと比較して類似度検索を実行します。

この方法なら、定義済みのキーワードに頼ることなく、自然言語を使って柔軟かつ直感的にクエリを実行できます。モデルが対応していれば、多言語での入力も可能です。システムはクエリにもっとも意味が近いアイコンを取得し、類似度スコアの順に並べるため、もっとも関連性の高い結果が最初に返されます。

**2. 事前計算済みのベクトルを使ったローカル検索**

アプリケーションには3つの定義済み検索ボタンがあり、それぞれに検索プロンプトが関連付けられています。

これらのプロンプトの埋め込みは一度だけ生成され、データベースに保存されています。

ユーザーがこれらのボタンのいずれかをクリックすると、アプリケーションは保存済みのベクトルをそのまま使い、OpenAI APIを再び呼び出すことなく類似度クエリを実行します。

これは、セマンティック検索を次のどちらの方法でも実行できることを示しています：

- 外部のAIサービスを使う（動的なクエリ）
- 以前に生成したベクトルを使ってローカルで実行する

このハイブリッドな方法により、セマンティック検索の高速性を保ちながら、API呼び出しを減らすことができます。

## ベストプラクティス

効率的でスケーラブルなセマンティック検索システムを構築するための要点を、次にまとめます：

- 一度ベクトル化して何度も使う：埋め込みをベクトル化の段階で生成して保存し、APIの繰り返し呼び出しを避けてパフォーマンスを高めます。
- 意味的な類似性を活用する：埋め込みを使って、メタデータとユーザーのクエリの概念的な関係をとらえます。
- ハイブリッド検索の戦略：OpenAIを使った動的な検索と、ローカルの事前計算済みベクトルを組み合わせて、APIの利用を減らし、クエリを高速化します。
- 拡張可能なアーキテクチャ：この方法は、文書、メディア、製品カタログ、ナレッジベースなど、ほかの分野にも応用できます。

### パフォーマンス／スケーラビリティ

大規模なデータセットでセマンティック検索を実装する場合は、パフォーマンスの最適化が重要です。

もっとも重要な推奨事項は、**ベクトル化の段階で埋め込みを生成し**、データベースに保存しておくことです。これにより、検索のたびに埋め込みサービスを呼び出さずに済みます。

もう1つの最適化の戦略は、サンプルアプリケーションのキーワードボタンで示したように、定義済みの検索には**保存済みのベクトルを再利用する**ことです。

## まとめ

ベクトル埋め込みを使ったセマンティック検索は、4Dアプリケーションにおけるアイコンライブラリの使いやすさを大きく向上させます。

アイコンのメタデータとユーザーのクエリの両方をベクトル表現に変換することで、システムは概念的な類似性を見いだし、キーワードの完全一致ではなく意味にもとづいてアイコンを検索できます。

**ORDA**、**4D.Vector**、**4D AI Kitコンポーネント**を使えば、開発者はAIを活用した最新の検索機能を4Dアプリケーションに簡単に組み込むことができます。

このアーキテクチャはアイコンライブラリにとどまらず、文書検索、メディア管理、ナレッジベースの探索など、高度な情報検索が求められるほかの多くの分野にも応用できます。
